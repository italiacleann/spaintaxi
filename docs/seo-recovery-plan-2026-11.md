## 1. Route consolidation

### How the decision was made

Redirecting one language of a route breaks hreflang for its sibling in the other language, so every decision is made **per route pair (EN + ES together)**:

- **Merge**: neither language version of the source route earned 10+ impressions in three months, and a reverse-direction page exists. Before redirecting, the departure details (pickup point, how early to leave, FAQ answers) are added to the destination page, so it genuinely covers both directions. Both languages redirect together, keeping the destination pair's hreflang intact.
- **Keep and improve**: at least one language version earned 10+ impressions. Redirecting would throw away a page Google already shows. Instead, the weaker language version is rewritten around departure logistics, with the travel-guide padding cut.

The "Links to update" column counts inbound links in the current build. Almost all come from the automatic related-routes engine and the hub pages, which update themselves once a route is removed from the data. Hardcoded content links that would need editing are listed separately.
